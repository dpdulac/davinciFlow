## 7. NATIVE OCIO v2.5.1 & CTF PIPELINE GENERATOR (`export_tmnt2_ocio2_ctf.py`)
To upgrade legacy OCIO v1 show transforms (such as TMNT2) to modern high-speed pipelines without loss of mathematical precision, provide a standalone generator script: `export_tmnt2_ocio2_ctf.py`.
- **Environment & Optimization**: Run within `rez env ocio-2.5.1 pyocio-2.5.1`. The script loads the legacy 15-operation show profile and applies `processor.getOptimizedProcessor(ocio.OPTIMIZATION_LOSSLESS)` to collapse redundant matrices and range operations down to an optimized 8-9 operation chain.
- **Color Transform Format (.ctf) Support**: Why `.ctf` instead of Academy `.clf`? Standard `.clf` does not support `InverseLUT1D` nodes and forces lossy inversion baking. Autodesk/Academy Color Transform Format (`.ctf`) natively supports `InverseLUT1D`, matrices, and range operators, guaranteeing 100% mathematical equality to the original studio shaders without highlight clipping or interpolation drift.
- **Outputs Generated**:
  1. `tmnt2_native_look_v2.ctf`: Linear `ACEScg` to `SPI_anim` Rec.709 display look.
  2. `tmnt2_acescct_to_rec709_v2.ctf`: Logarithmic `ACEScct` to `SPI_anim` Rec.709 display look.
  3. `tmnt2_config_v2.ocio`: A lightweight, standalone OCIO v2.1 configuration file referencing the native CTF shaders for instant loading in DCCs and DaVinci Resolve.

### Loading `.ctf` and OCIO v2 in DaVinci Resolve
Because `.ctf` is an active OpenColorIO shader format containing complex mathematical formulas (like `InverseLUT1D`), DaVinci Resolve will **not** list it in the static right-click LUT menu (which only registers table formats like `.cube`, `.3dl`, or `.clf`).
To load the `.ctf` look in Resolve 21:
1. Go to the **Color Page** and open the **Effects (OpenFX)** panel.
2. Under **Resolve FX Color**, drag and drop **OCIO Display** (or **OCIO ColorSpace**) onto your color node.
3. In the Inspector / Settings panel:
   - Change **OCIO Config** from Default to **Custom File...** (or **FromFile**).
   - Browse and select the standalone config file: `/s/prodanim/studio/_sandbox/dulacd/tmnt2_config_v2.ocio` (or `/datas/dulacd/tmnt2_config_v2.ocio`).
   - Set **Input Color Space**: `ACEScg` (for EXR) or `ACEScct` (for Log).
   - Set **Display Device**: `Rec.709-Screen`.
   - Set **View Transform**: `SPI_anim`.

### Dual-Workflow Architecture: Why `.cube` is Slower or Faster than OCIO Display
When testing timeline performance in DaVinci Resolve, you will notice that using an **OCIO Display** node is significantly slower than applying the baked **`.cube`** 3D LUT. This is intentional and comes down to hardware rendering architecture:
- **Why OCIO Display (.ctf) is Slower in Resolve**: OpenFX (OFX) plugins execute outside Resolve's ultra-fast core color node loop, adding API overhead per frame. More importantly, executing an OCIO v2 `.ctf` shader requires the GPU to actively compute an 8- to 9-step mathematical chain—performing matrix multiplications, power curves, and iterative floating-point approximations for `InverseLUT1D` tables—per pixel on every single frame.
- **Why `.cube` is Blazing Fast in Resolve**: When applying a `.cube` LUT directly on a node (or via a CST node), DaVinci Resolve loads the static 3D lookup table directly into GPU video memory as a 3D texture. Resolve's hardware shaders perform instantaneous tetrahedral interpolation with essentially zero computational overhead.

**Industry Standard Recommendation:**
- **For DaVinci Resolve (Real-Time Review & Editorial)**: Always use the **`CST (ACEScg ➔ ACEScct)` + `tmnt2_acescct_to_rec709.cube`** workflow (automatically applied by `davinciFlow` via `drx/tmnt2_0cio_exr.drx`). Converting scene-linear EXRs into log first preserves >1.0 highlight dynamic range without clipping while delivering smooth real-time 24fps/30fps playback.
- **For DCCs & Compositing (Nuke / Katana / Houdini / Arnold)**: Use the **`tmnt2_config_v2.ocio` and `.ctf` shaders**. Lighting and compositing software does not rely on real-time editorial playback; instead, they require 100% mathematically exact float32 calculations without table interpolation tolerances.

### Standalone AgX Color Science Pipeline (`export_agx_pipeline.py`)
To democratize AgX grading across the studio without relying on external DCTL files or system-wide OCIO installations, we provide `export_agx_pipeline.py`.
- **Mathematical Architecture**: Implements industry-standard AgX (by Troy Sobotka) directly in Python and PyOpenColorIO 2.5.1 using vector math and NumPy. It handles chromaticity rotation to AgX inset primaries, log encoding (-10.0 to +6.5 EV), and applies the smooth AgX Punchy filmic tone mapping curve.
- **Why Eliminate DCTLs?**: Custom DaVinci DCTL shaders often fail across different OS platforms (Linux vs Windows) or when external studio files are missing on local disk. Baked 65x65x65 3D LUTs run natively on Resolve's hardware GPU engine at zero computational overhead and require zero external plugins.
- **Outputs Generated & Deployed**:
  1. `agx_acescct_to_rec709.cube` & `.ctf` (for scene-linear EXRs via log buffering).
  2. `agx_rec709_proxy.cube` & `.ctf` (for display-referred video proxies).
  3. `agx_srgb_img.cube` & `.ctf` (for sRGB textures and stills).
  4. `agx_config_v2.ocio`: A standalone OCIO v2.1 profile deployed to user sandboxes (`/datas/dulacd/` and the centralized studio sandbox `/s/prodanim/studio/_sandbox/dulacd/`) so lighting and compositing artists in Nuke/Houdini/Katana can access identical AgX color responses across all studio shows.

### Centralized Studio OCIO v2 Repository (`/s/prodanim/studio/_sandbox/dulacd`)
All generated standalone OCIO v2 configurations (`tmnt2_config_v2.ocio`, `agx_config_v2.ocio`) and native Color Transform Format shaders (`.ctf`) are globally hosted in **`/s/prodanim/studio/_sandbox/dulacd/`** rather than show-specific production sandboxes (such as `tmnt2/_sandbox`).
- **Why Centralize in Studio Sandbox?**: Placing color configurations in the global `studio/` sandbox guarantees universal accessibility across diverse studio productions, lighting workflows, and visual effects applications (Nuke, Houdini, Katana, Blender, Renderers). Artists on any show can reference these unified OCIO profiles without encountering show-specific storage access bottlenecks or duplicating files across project hierarchies.
- **Repository Contents at `/s/prodanim/studio/_sandbox/dulacd/`**:
  - **AgX Suite**: `agx_config_v2.ocio`, `agx_acescct_to_rec709.ctf`, `agx_rec709_proxy.ctf`, `agx_srgb_img.ctf`, and associated `.cube` files.
  - **TMNT2 Suite**: `tmnt2_config_v2.ocio`, `tmnt2_native_look_v2.ctf`, `tmnt2_acescct_to_rec709_v2.ctf`, and associated `.cube` files.

## 8. INSTALLATION & DEPLOYMENT GUIDE

**IMPORTANT RULES FOR DAVINCI RESOLVE SCRIPT DIRECTORY:**
DaVinci Resolve automatically scans any `.py` file placed inside its Utility scripts folder and lists it in the **Workspace > Scripts > Utility** top menu. To prevent menu clutter, artist confusion, and execution errors from running standalone CLI baking tools inside Resolve's Python runtime, **YOU MUST ONLY INSTALL `davinciFlow.py` (along with `configs/`, `drx/`, and JSON config files) INTO RESOLVE'S SCRIPT DIRECTORY!**
All standalone ("outside") generator and baking scripts (`export_agx_pipeline.py`, `export_tmnt2_ocio2_ctf.py`, `bake_tmnt2_acescct_lut.py`, `generate_luts.py`) must remain safely stored in the GitHub repository and executed from a terminal when color pipeline updates are required.

**1. Installing `davinciFlow` into DaVinci Resolve:**
Copy **only** `davinciFlow.py`, `davinciFlow_config.json`, `userpref.json`, and the `drx/` and `configs/` directories into your DaVinci Resolve Fusion Scripts Utility directory:
- Linux: `/datas/dulacd/DaVinciResolve/Fusion/Scripts/Utility/davinciFlow/`
- Windows: `%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Fusion\Scripts\Utility\davinciFlow\`
*(Do NOT copy generator `.py` scripts or heavy `.cube` / `.ctf` / `.ocio` files into this scripts directory).*

**2. Deploying LUTs & CTF Color Profiles:**
Copy generated 3D LUTs (`tmnt2_acescct_to_rec709.cube`, `agx_acescct_to_rec709.cube`, `agx_rec709_proxy.cube`, `agx_srgb_img.cube`) into your system DaVinci Resolve LUT directory under a `davinciFlow` subfolder:
- Linux: `/datas/dulacd/DaVinciResolve/LUT/davinciFlow/` (or `~/.local/share/DaVinciResolve/LUT/davinciFlow/`)
- Windows: `C:\ProgramData\Blackmagic Design\DaVinci Resolve\Support\LUT\davinciFlow\`
For standalone DCC usage (Nuke 16, Houdini, Katana, Arnold), copy the OCIO profiles (`tmnt2_config_v2.ocio`, `agx_config_v2.ocio`) and native `.ctf` shaders to the centralized studio sandbox (`/s/prodanim/studio/_sandbox/dulacd/`) or workstation root (`/datas/dulacd/`).

**3. Setting up `tmnt2_0cio_exr.drx` for Fast Playback:**
If you need to rebuild the `.drx` file for the TMNT2 look, create this specific node tree in the Color Page and export it as `tmnt2_0cio_exr.drx` to the plugin's `drx/` folder:
- **Node 1: Color Space Transform (CST)**
  - Input Color Space: `ACES (AP1)` or `ACEScg` | Input Gamma: `Linear`
  - Output Color Space: `ACES (AP1)` or `ACEScct` | Output Gamma: `ACEScct`
- **Node 2: 3D LUT (Recommended for Real-Time Playback)**
  - Apply the `davinciFlow/tmnt2_acescct_to_rec709.cube` 3D LUT directly from the right-click LUT menu.

**4. Setting up `AgX_exr_cst.drx` for Fast AgX Playback on EXRs:**
Because EXR files are scene-linear with HDR values above 1.0, applying a LUT directly without log compression would clip high luminance highlights. To create the DCTL-free AgX powergrade for EXRs:
1. In DaVinci Resolve, select an EXR clip and open the **Color Page**.
2. Create two serial color nodes:
   - **Node 1: Color Space Transform (CST)**: Input `ACEScg` (Linear) ➔ Output `ACEScct` (ACEScct Log). No Tone/Gamut Mapping.
   - **Node 2: 3D LUT**: Assign **`LUT -> davinciFlow -> agx_acescct_to_rec709`**.
3. Grab a Still in the Gallery, right-click the thumbnail, select **Export...**, and save as **`AgX_exr_cst.drx`** directly into your `drx/` folder.

## 9. STANDALONE ("OUTSIDE") PIPELINE GENERATION SCRIPTS & TOOLS

The GitHub repository (`/datas/dulacd/gitHub/davinciFlow/`) includes several standalone Python pipeline tools designed for external execution from a Linux/Windows terminal or desktop environment. These scripts serve as the foundational color generators and administration utilities for the studio ecosystem. 
**Why must they be run outside DaVinci Resolve?** Because they manipulate OpenColorIO 2.5.1 C++ bindings, generate high-resolution color lattices via NumPy math, run external PySide6 GUIs, and manage disk-level deployments across studio sandboxes without interacting with Resolve's active project runtime.

> [!CAUTION]
> **STRICT RESOLVE FOLDER EXCLUSION RULE:** None of the scripts listed below (`userpref_manager.py`, `export_*`, `bake_*`, `generate_*`, or launcher scripts) may ever be present inside DaVinci Resolve's active script installation directory (`/datas/dulacd/DaVinciResolve/Fusion/Scripts/Utility/davinciFlow/`). Any Python script in that folder directly pollutes the DaVinci Resolve menu. Only `davinciFlow.py` belongs in the Resolve application directory!

### 1. `export_agx_pipeline.py` (AgX Color Profile Generator)
- **Purpose**: A comprehensive color science baker that builds Troy Sobotka's AgX imaging architecture from scratch using OpenColorIO 2.5.1 and NumPy mathematics.
- **How it Works**: Calculates chromaticity rotation to AgX inset primaries, applies log2 dynamic range encoding (-10.0 EV to +6.5 EV), and computes the custom AgX Punchy filmic tone mapping response.
- **Outputs**: Produces three ultra-precise `65x65x65` LUTs and `.ctf` transforms (`agx_acescct_to_rec709`, `agx_rec709_proxy`, and `agx_srgb_img`) alongside a master `agx_config_v2.ocio` configuration file.
- **Execution**: Run from a terminal via `rez env ocio-2.5.1 pyocio-2.5.1 -- python3 /datas/dulacd/gitHub/davinciFlow/export_agx_pipeline.py`.

### 2. `export_tmnt2_ocio2_ctf.py` (TMNT2 OCIO v2 & CTF Upgrader)
- **Purpose**: Modernizes legacy studio show color transforms (specifically the TMNT2 15-operation OCIO v1 pipeline) into lossless OpenColorIO v2.1 architectures.
- **How it Works**: Ingests legacy look files and utilizes OCIO's lossless optimization processor (`OPTIMIZATION_LOSSLESS`) to collapse redundant matrices and scaling loops into an efficient 8-9 operation shader chain. Crucially, it exports directly to Autodesk/Academy Color Transform Format (`.ctf`), which natively supports exact algorithmic `InverseLUT1D` evaluation without forcing lossy inversion baking or causing Nuke 16 segmentation faults on non-invertible tone curves.
- **Outputs**: Generates `tmnt2_native_look_v2.ctf` (Linear ACEScg), `tmnt2_acescct_to_rec709_v2.ctf` (Log ACEScct), and `tmnt2_config_v2.ocio`.
- **Execution**: Run from a terminal via `rez env ocio-2.5.1 pyocio-2.5.1 -- python3 /datas/dulacd/gitHub/davinciFlow/export_tmnt2_ocio2_ctf.py`.

### 3. `bake_tmnt2_acescct_lut.py` (Real-Time Resolve LUT Baker)
- **Purpose**: A targeted LUT baking utility engineered explicitly to solve DaVinci Resolve real-time playback bottlenecks. While `.ctf` shaders provide 100% mathematical precision for DCC compositing in Nuke/Katana/Houdini, running OFX OCIO Display shaders in DaVinci Resolve incurs heavy frame-by-frame GPU matrix calculation overhead.
- **How it Works**: Samples the exact TMNT2 OCIO color transforms across an intermediate logarithmic ACEScct space to bake an unclipped, tetrahedrally interpolatable `65x65x65` 3D cube.
- **Outputs**: `tmnt2_acescct_to_rec709.cube`, which is loaded directly into GPU texture memory by Resolve's native Color Space Transform nodes (`drx/tmnt2_0cio_exr.drx`) to achieve blazing-fast real-time 24/30fps review playback.
- **Execution**: Run from a terminal via `rez env ocio-2.5.1 pyocio-2.5.1 -- python3 /datas/dulacd/gitHub/davinciFlow/bake_tmnt2_acescct_lut.py`.

### 4. `generate_luts.py` (Mathematical B&W Review LUT Baker)
- **Purpose**: Generates high-precision Black & White conversion LUTs used during review sessions when "Review Shots" filtering is active (rendering hero shots in full color and non-hero shots in grayscale to guide directorial focus).
- **How it Works**: Uses standard ITU-R Rec.709 relative luminance weighting formulas ($L = 0.2126R + 0.7152G + 0.0722B$) across 33³ and 65³ 3D lattices to mathematically transform standard studio look LUTs and proxy color spaces into uniform monochrome profiles without requiring external grading software.
- **Outputs**: `proxy_bw.cube` and show-specific B&W EXR LUT variants.
- **Execution**: Run directly via terminal Python: `python3 /datas/dulacd/gitHub/davinciFlow/generate_luts.py`.

### 5. `userpref_manager.py` & Launchers (Artist Preset Desktop GUI)
- **Purpose**: A standalone PySide6 / Qt graphical user interface that empowers review artists and supervisors to construct, modify, and save custom task discovery hierarchies without manually editing JSON configs.
- **How it Works**: Reads master tasks and provides an interactive reorderable checklist. Saved presets are written directly to `userpref.json` (or `~/.flowDavinciData/userpref.json`), which `davinciFlow.py` automatically imports to populate the **Task Preset Combo** inside Resolve's UI.
- **Execution**: Launched as a standalone desktop app before or during editing sessions using the accompanying shell scripts: `./Launch_UserPref_Manager.sh` (Linux/Mac) or `Launch_UserPref_Manager.bat` (Windows).
